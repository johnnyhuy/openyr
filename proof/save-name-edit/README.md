# Save-name editing proof

Two verified executable/source receipts drive live Linux Xorg sessions: main e60d24f before the fix, and the committed fixed source including the README refresh. Xorg, guarded native app launch, public XTest input and ImageMagick capture run in one task session. The capture opens Pause/Save, clears the default name, types 47 W characters plus A, backspaces and types B, repeats that edit and saves.

At 640x480, the old name-A and name-B field pixels are identical: the edited suffix is hidden. The fixed field changes and shows its hidden-prefix marker, ending letter and caret. At 1280x800 both versions show the suffix, preserving the fitting-name behavior. Retyping B reproduces its field exactly. All four cases create the full 48-character filename. Each resulting save is loaded and saved again through the corresponding guarded native executable, producing byte-identical files. Hashes and field rectangles are in the receipts. Cross-run hashes may differ because live simulation ticks precede Pause; equality is asserted within each actual roundtrip.

The new compositor regression fails against old main and passes for fallback and retail fonts at three sizes. Unicode, caret fitting and narrow fields are checked separately. The actual-handler test verifies append/backspace, the input cap, full filename and unchanged complete live/file snapshot bytes. Workspace tests passed 464 with one existing audio-device test ignored; strict Clippy and fmt passed. README local links resolve, and its feature/setup/control/proof documentation was refreshed at the user's request.

Full compact captures and all field crops are included. Generated saves, executables and raw assets are excluded. No original executable was run or inspected. Original caret styling/timing and physical Mac/Retina input remain open. Known permission-blocked macOS/reference capture paths and the earlier HTTP-401 release-upload route were skipped.
